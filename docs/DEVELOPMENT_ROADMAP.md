## 최종 포트폴리오 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│                      Core Service (Vinyler API)               │
│           회원 · 리뷰 · 좋아요 · 감상 · 팔로우                  │
└───────────────┬─────────────────────────────┬───────────────┘
                │                             │
        ┌───────▼────────┐           ┌────────▼─────────┐
        │  Search Layer  │           │   Event Layer    │
        │ Elasticsearch  │           │  Domain Event +  │
        │ 자동완성/오타허용 │           │  Redis Stream    │
        └───────┬────────┘           └────────┬─────────┘
                │                             │ (consumer)
                │                    ┌────────▼─────────┐
                │                    │ Statistics Layer │
                │                    │ 인기 LP(Redis ZSET)│
                │                    │ 장르 트렌드 집계   │
                │                    └────────┬─────────┘
                │                             │
        ┌───────▼─────────────────────────────▼─────────┐
        │           Batch Layer (vinyler-batch)          │
        │  가격 수집 · 리뷰 집계 · 트렌드 계산 · 임베딩 색인 │
        └───────┬────────────────────────────────────────┘
                │
        ┌───────▼────────┐
        │    AI Layer    │
        │ Qdrant·Embedding│
        │ LP추천·의미검색  │
        └────────────────┘

Infra: Docker Compose · Redis · Elasticsearch · MySQL · AWS ECS/EC2
```

**설계 포인트 (면접 설명용)**
- 실시간 집계(인기 LP, Redis Sorted Set)와 일배치 집계(장르 트렌드, Spring Batch)를 **의도적으로 분리** — "실시간 vs 배치" 트레이드오프 설명.
- 배치 서버를 단순 집계가 아니라 **AI 데이터 파이프라인**(임베딩 생성 → Qdrant 색인)으로 포지셔닝 — JD의 "데이터 엔지니어링" 영역에 직접 매칭.
- 통계/알림 기능을 Domain Event 위에 얹어 **이벤트 기반 디커플링** 아키텍처로 구성.

## 고도화 로드맵 (7월, 약 1개월)

> 개발 순서 확정: ① ES → ② Domain Event/Redis Stream → ③ 인기 집계 → ④ 배치 분리 → ⑤ 가격 변동 → ⑥ SSE 알림 → ⑦ Qdrant+RAG(차차)

> 토대 단계. 현재 `title LIKE '%...%'` 수준을 Elasticsearch로 교체. RAG 검색의 기반이기도 함.

|---|---|---|---|---|---|

| ☐ | 색인 매핑 설계 | Vinyl 문서 매핑 (artist/title/genre/year/country) | 07-02 | 07-03 | |
| ☐ | DB → ES 초기 색인 | 기존 Vinyl 데이터 일괄 색인 | 07-03 | 07-04 | |

## 사수 우선순위 (시간 부족 시 위에서부터 지킴)

1. **Phase 1 ES 검색** — 없으면 RAG 토대도 없음
2. **Phase 3 배치 + 임베딩 색인** — 데이터 파이프라인 스토리 + RAG 데이터 확보
3. **Phase 5 RAG 추천** — AI 백엔드 차별화의 핵심 (Phase 3 데이터 있으면 빨리 완성)
4. **Phase 2 인기 집계** — 싸고 효과 큰 보너스
5. **Phase 4 이벤트/SSE 알림** — 여유분

> 핵심 원칙: 못 끝낼 거라면 **알림 스택을 버리지 RAG를 버리지 않는다.** 단, Phase 3에서 임베딩 데이터를 미리 쌓아두면 RAG가 "영영 안 함"이 되는 걸 막을 수 있다.
